Этот чеклист отделяет уже доказанные автоматикой release-gates от физических эксплуатационных проверок, которые GitHub Actions честно заменить не может.

- [x] `python release_check.py` проходит в обязательном CI (`Run release gate`).
- [x] Чистый source-archive собирается в обязательном CI (`Build clean source archive`).
- [x] Windows build проходит на GitHub-hosted Windows runner.
- [x] Реальный Tk GUI wiring smoke проходит до упаковки.
- [x] PyInstaller EXE собирается и запускается после сборки.

## P0 — физические проверки перед коммерческим запуском

Эти пункты намеренно остаются ручными: они зависят от конкретной рабочей станции, Microsoft Word/Office, принтера, репутации подписи и корпуса реальных обезличенных документов.

- [ ] EXE запускается на отдельной чистой Windows-машине без установленного Python/pip.
- [ ] На целевой машине проверен legacy `.doc` с установленным Microsoft Word; исходный `.doc` остаётся неизменным.
- [ ] Windows Defender / SmartScreen проверены на целевой пользовательской машине.
- [ ] Для публичного коммерческого релиза настроен и проверен Authenticode code-signing, если используются соответствующие credentials.
- [ ] На живом пользовательском наборе проверены сценарии: выбрать первичный документ, выбрать ЭПИ, выбрать тексты дневников, выбрать папку «шаблоны дневников», создать без печати, создать и распечатать.
- [ ] На живых шаблонах проверены все используемые врачом документы: первичный, выписной, комиссия, ВК на МСЭ, акт, направление, РВК.
- [ ] На живом сценарии больничного листа подтверждено: popup номера ЛН открывается только для выписного эпикриза при выбранном «нужен больничный лист».
- [ ] Проверена печать на реальном Windows-принтере и сценарий «принтер не выбран / недоступен».
- [ ] Проверены 20–50 обезличенных реальных DOCX/DOCM/DOC-наборов из фактической практики.

## P1 — коммерческий запуск

- [ ] Подготовлена страница/лендинг с честным описанием: программа локальная, документы не отправляются в облако.
- [ ] Подготовлена короткая инструкция для пользователя: скачать installer/EXE, открыть, выбрать документы, сохранить/распечатать.
- [ ] Подготовлен способ поддержки: куда прислать обезличенный пример, технический лог или скрин ошибки.
- [ ] Подготовлена политика обработки данных: медицинские документы остаются у пользователя локально.
- [ ] Подготовлен rollback: предыдущий стабильный installer/EXE и source-archive сохранены.

## P2 — после первых пользователей

- [ ] Собирать реальные ошибки только на обезличенных примерах.
- [ ] Добавлять regression/smoke-тест на каждый повторяющийся сбой до исправления.
- [ ] Отслеживать востребованность типов документов без сбора персональных медицинских данных.

## Правило статуса

Зелёный CI означает, что программный release-контур доказан в автоматизированной среде. Он не является заменой физической проверке конкретного принтера, конкретной Windows-конфигурации, SmartScreen reputation или реального корпуса медицинских документов.
