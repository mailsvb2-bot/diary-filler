# Папка «Выписанные пациенты»

Это дополнительный Windows-контур удобства вокруг существующего `diary-filler`.
Он **не заменяет и не изменяет** механику разбора первичного документа,
popup-диалоги, выбор создаваемых документов, заполнение шаблонов или генерацию
дневников.

## Пользовательский сценарий

1. После первого обычного запуска обновлённой программы на рабочем столе
   автоматически создаётся папка `Выписанные пациенты`.
2. В автозагрузку текущего пользователя устанавливается скрытый наблюдатель.
   Отдельная Windows-служба и права администратора не нужны.
3. Врач просто переносит первичный DOCX/DOCM или направление на госпитализацию
   в верхний уровень папки `Выписанные пациенты`.
4. Наблюдатель ждёт окончания копирования файла, проверяет, что это действительно
   первичный документ/направление, и запускает тот же `MedicalDiaryAutofill.exe`.
5. Для пациента создаётся подпапка. По умолчанию имя строится в совместимом с
   Dokkomplekt виде: `Фамилия И.О. месяц год`, например
   `Иванов И.И. май 2026`.
6. Первичный документ переносится в подпапку пациента.
7. Программа передаёт перемещённый файл в свой штатный
   `_apply_primary_document_path(...)`. С этого места работает только прежняя
   механика `diary-filler`.
8. Поскольку штатный `diary-filler` использует родительскую папку первичного
   документа как папку результата, создаваемые документы автоматически
   оказываются в подпапке пациента.

## Защита от ошибок

- сканируется только верхний уровень `Выписанные пациенты`; готовые подпапки
  пациентов повторно не обходятся;
- временные Word-файлы `~$...` и скрытые файлы игнорируются;
- файл не открывается, пока копирование не стабилизировалось;
- выписные/переводные/этапные эпикризы, дневники, протоколы и согласия не
  принимаются за первичный документ;
- повторно брошенный байт-в-байт тот же первичный не создаёт второго пациента;
- другой файл при совпадающем имени папки получает безопасный суффикс `(2)`,
  `(3)` и т.д.;
- если GUI уже открыт, фоновый агент не поднимает второе окно: активность GUI
  определяется техническим heartbeat без данных пациента;
- технический лог агента не записывает ФИО и имена пациентских файлов.

## Формирование имён подпапок

Движок именования поддерживает совместимые части:

- полное ФИО;
- фамилия + инициалы;
- фамилия + имя;
- дата поступления;
- дата выписки;
- обе даты;
- месяц поступления;
- месяц выписки.

Безопасный intake-default — `surname_initials + admission_month`, потому что эти
данные известны уже в момент переноса первичного документа. Части, зависящие от
даты выписки, поддерживаются движком, но intake не выдумывает отсутствующую дату
и не вмешивается ради неё в генерацию документов.

## Архитектурная граница

Новые модули отвечают только за внешний workflow:

- `desktop_patient_folder.py` — имя подпапки;
- `desktop_intake.py` — обнаружение, проверка, дедупликация и перенос;
- `desktop_intake_agent.py` — скрытый watcher/autostart;
- `desktop_intake_workflow.py` — передача готового пути в существующий GUI.

Модули `medical_*`, `diary_*`, `actions_creation*`, шаблоны и правила создания
медицинских документов этим изменением не модифицируются.

Для диагностики автоматический intake можно временно отключить переменной:

```bat
set MEDICAL_AUTOFILL_DISABLE_DESKTOP_INTAKE=1
```

Headless-контракт:

```bat
python desktop_intake_contract_check.py
```
